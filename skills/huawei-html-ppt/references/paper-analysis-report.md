# 论文分析报告

论文汇报使用洞察分析分支，以论文提出的问题、创新机制和实验依据组织内容。用户有指定结构时优先遵从；下列是已确认的默认形式，不套到普通模型对比或技术项目上。

## 封面与章节顺序

默认顺序：**封面 → 目录（核心创新高亮）→ 核心创新 → 目录（下一章高亮）→ 各创新点的设计与机制 → 可选的对照/应用分析 → 目录（实验高亮）→ 实验结果**。

- 封面标题用“【论文题目】论文分析报告”，可自然换行。采用 PDCP 封面的上方黑色大标题、红色角线、背景区与底部白色区域。日期由本次材料或用户确认，不复制参考页的作者、部门、日期。
- 有用户提供或可复用的本地封面背景时使用原图；通过 `background` 参数传入并记录来源。没有背景时使用浅灰底。组件不携带参考照片、整页截图或整套 PPT 模板。
- 每一章前重复同一份完整目录，当前章放大并标红。目录包含“核心创新”；其正文放在对应目录之后，不提前放在封面与目录之间。
- 目录为浅灰底、黑色“目录”标题、短红线和左侧编号列表。只显示一级章节。章节较多时先合理合并到不超过八项，不靠小字挤入。
- 章节标题、顺序和高亮来自同一份数据，避免维护多份目录后漏项或错位。一章可有多页，不要求每个内容页前都重复目录。
- 正文标题直接说明内容，例如“分别验证训练监督和推理路径的作用”，不再加“模块一／模块二”等目录已表达的编号。
- 封面和目录只负责标识与导航，无需分析结论、图表或装饰性填充。正文继续保留具体分析结论及图文证据。

## 内容组织

核心创新页先回答论文改变了什么、如何做到、什么证据支持。后续各章分别展开每个创新点的设计、训练或推理机制及其作用。对照与应用分析放在实验之前，按实际需要安排。

实验集中收尾，按主要结果、消融和限制组织。区分论文报告结果、源码实现、复现实验和自己的推断；条件和比较口径影响结论时直接写在正文，来源及制作记录放备注。不能将论文中的研究模型或实验收益直接套到另一个线上模型。

优先复用论文原图。机制图说明论文实际支持的内容；没有运行实现证据时不编造融合算子、shape、通信或硬件结果。图表、结论表达继续遵循洞察分析规范。

## 通用组件与接口

`scripts/paper_report.py` 的 `assemble(title, chapters, cover=None)` 生成标准页面顺序，之后直接调用 `ppt.render`，不需要在 HTML 生成后手动插页或修改页码。

```python
deck = paper_report.assemble(
    title="某项研究论文分析报告",
    chapters=[
        {"id": "innovation", "title": "核心创新", "slides": innovation_slides},
        {"id": "design", "title": "设计与机制", "slides": design_slides},
        {"id": "results", "title": "实验结果", "slides": experiment_slides},
    ],
    cover={"title": "某项研究\n论文分析报告"},
)
result = ppt.render({"content_kind": "paper-analysis", "deck": deck}, output_dir)
```

`slides` 使用原有洞察内容页字段，结论和图表由宿主根据材料编写。各创新点可拆成独立章节，也可在一章内用多页展开。`cover` 可提供日期和本地 `background` 图像对象；图像字段与普通 `image` 一致，要求绝对路径、`alt` 和来源。正文、目录和封面统一保存到 `deck-model.json`，`validate` 核对高亮章节、章节归属及排列顺序。

布局定义见 [paper-frontmatter.json](../assets/units/paper-frontmatter.json)，字段见 [运行接口](runtime-contract.md#论文报告)。
