# 组件复用与绘图验收

用于结构、机制和变化放大图。曲线、柱状图、表格继续按数据问题选择，不要求塞入结构组件。这里复用布局和端口，不复用其他模型的数字或拓扑。

## 实际生成

`plan` 返回 `component_builders`，定义位于 `assets/components/catalog.json`，实现位于 `scripts/diagram_components.py`。按用途选少量组件：完整主干、MoE分支、前后变化定位、残差混合、循环状态或池化索引。参数必须来自本次材料；不要把普通MoE画成Latent MoE。

```python
from diagram_components import Diagram
g = Diagram('MoE 分支')
ports = g.use('moe-routing', 'moe', 15, 40, 800, 230,
              hidden=4096, intermediate=2048, experts=288, top_k=8, shared=1)
data = g.contract('mechanism',
    paths=[[ports['input'], ports['experts'], ports['output']],
           [ports['input'], ports['shared'], ports['output']]])
```

该例只是调用方式；数字是演示参数，不能作为其他模型默认值。`use` 实际运行构图，记录组件版本、参数、几何范围及摘要；组件之间通过具名端口连接。可按空间整体等比缩放，不能靠压扁组件挤满版面。

新材料不适用已有构图时，可用 `Diagram.node/connect/matrix` 补充图元并定义新的小组件，或调整组合关系。不要为了通过检查伪造组件使用记录。不要把整页报告固化为一个组件。固定宽高只约束组件的内部比例，页面布局、图表种类和内容数量仍按材料决定。

`comparison-table` 用于结构总览旁的关键参数表，通过 `changed_rows` 只强调真实变化；`memory-budget` 接收本次核算的容量与分项，不内置特定硬件容量或系统预留。完整参考报告及学习记录留在项目目录，只将这些最小表达方式和通用规则纳入skill。

`pd-state-transfer` 分别呈现P/D并行配置、节点、物理卡与rank数量，以及有读写箭头的状态交接。P/D规模通过各自的`nodes/cards_per_node/ranks_per_node/parallel`传入；`states`只列本模型真实需要迁移的1–4类状态。组件不解析并行字符串来证明进程组正确，也不假设一卡一rank；这些由场景底稿核验。

## 两层验收

新报告顶层设置 `diagram_contract: 1`。每张图声明 `acceptance`，包括必要节点、必须连通的路径、总览到放大的关系。`validate`/`diagram_audit.py`检查：

- 组件能否从记录参数重放，图形和具名节点是否与记录一致。
- 主输入到输出、路由专家和共享专家到汇聚点的路径是否存在。
- 标记需要I/O的缓存是否同时画出写入和读取。
- 声明的放大关系是否存在可见连线；图形是否越界、文字是否违反颜色规范。

结构检查不能判断数据真实、机制是否讲清或画面是否好看。实际查看渲染图时，还要对照来源与参考样例：

1. **整体图**：模型输入、重复范围、例外层、输出齐全；关键分支展开到能解释结论的程度。
2. **变化图**：先定位基线和新版本的不同，再关联放大。继承、新增、替换分别标明，不能让红色表示不明确。
3. **图形语义**：张量/矩阵、专家组、缓存、运算和通信用合适的表达，不退化成同一规格的方框链。
4. **阅读效果**：按实际显示尺寸检查文字与线交叉、长线绕行和大块无意义留白；必要时减少旁边解释，给图腾出面积。

将实际查看记录放项目目录，例如 `visual-review.json`：保存 reviewer=`agent`/`user`、对应文件和截图摘要、逐项判断及尚未解决的问题。只有真实用户确认才可写 reviewer=`user`。参考图是质量依据，不要求照搬不适用的技术结构。

旧报告没有语义契约时仍能渲染；检查会提示它只具备旧几何检查。新增和重做的结构图采用此流程，避免一次更新破坏历史文件。
