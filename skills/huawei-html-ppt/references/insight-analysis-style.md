# 洞察分析风格

与涉及模型的技术项目共用 [数据与分析流程](source-acquisition.md)。模型对比和单个模型上的特性分析都先核对结构、实现和场景，再组织变化、机制、收益与限制；不因汇报风格不同重复维护另一套事实。

用于模型/特性原理、结构变化、性能与资源分析、选型和亲和性判断。

## 页首

每页都保留显式“分析结论”栏：标题下方放红底白字“分析结论”标签，右侧通栏浅灰底承载关键判断。标题可以表达判断，但不能代替或省略结论栏。结论通常1–2行，先写影响或判断，再写适用条件；不要把来源和制作批注放入该栏。

此规则与技术项目页的“挑战＋目标／目标＋进展”成对摘要分开：洞察分析使用单个通栏结论块，主体仍按结构、机制、证据选择不同布局。

结论承担本页摘要：概览页提炼关键结构和变化，机制页解释影响，性能页指出瓶颈，部署页给出配置、条件和容量结果。允许基于证据给出自己的判断及取舍，不强求每页都写建议，也不用“需关注、待验证”代替分析。按 [结论写法](insight-conclusions.md) 执行；详细参数可紧邻图表列成短条目，不因结论栏较短而删掉关键事实。

## 已确认的默认图形风格

下面的已确认样式适用于结构和机制图；数据分析按 [chart-selection.md](chart-selection.md) 优先选择简单曲线、柱状图或对比表，不受固定结构图布局限制；复杂图不作为报告正文的默认选择。

结构和机制图按本次内容组织，复用已确认的图形语言，不把某个案例的版式当作固定要求。完整主干应表达输入输出、重复范围与关键分支；变化可直接在结构中标明，也可用前后对照。
- 图中文字、边注和尺寸为黑灰，关键变化可红色；低饱和填充服务于分组，不按模块轮换文字颜色。

按需从 [组件目录](../assets/units/catalog.json) 选取小单元。组件只提供表达方式，不包含真实模型拓扑；具体层数、维度和分支必须来自本次材料。

标题可直接写对象与内容，不要求使用判断式长句；关键结论由下方“分析结论”栏清楚说明。正文表达按 [style-guide.md](style-guide.md) 的写作规则。

## 页面布局

### 模型洞察的核心页

首个内容页默认参考“左侧结构总览＋右侧关键参数/变化表”，并保留上方分析结论。结构图保留完整输入输出与关键模块；表格只突出当前模型与基线的实际变化。无可比基线时列关键参数和待确认项，不编造对照对象。不要把首页改成纯评测表而缺少结构入口。

模型报告要有专门页面承载“代际显存预估与部署模式”。A3/A5按本次场景分别核算，列明权重、缓存/状态、通信及系统/工作区开销、统计粒度和P/D配置；有可靠明细时使用分项表、简明容量条带及上下文变化表。缺少实测或分项依据时保留理论估算与未知项，不能套用参考案例的OS、HCCL、量化参数或把未知空间写成可用容量。不同硬件内容多时分两页，内容少时同页并列。

当需要同时给出A3/A5部署建议时，优先各用一页；结论写清模型、P/D设备或节点数、DP/TP/EP等具体组合和上下文条件，并给出同口径的每rank显存结果。按 [部署分析](ascend-deployment-analysis.md) 连接结构变化、资源分项与选择理由。将推荐验证起点、估算和实测区分开，不用“已有示例、还需测试”替代具体部署判断。权重按TP/EP、复制张量及缓存各自布局核算；HCCL_BUFFSIZE等配置项不能直接当作运行时总显存。

模块变化小，优先让总览、变化对比及资源部署页讲清楚；变化大时再按实际模块拆页说明。需要论证并行调优时，增加“算子/通信路径＋同口径策略对比＋容量或性能依据”页，不只罗列TP/EP/PP/PCP/DCP名称。页数服从信息，不固定成三页或其他数量。

- `insight-system`：整体数据流/执行域占大部分画布，右侧窄栏给关键判断。
- `insight-zoom`：保留完整主干，使用虚线定位并放大版本变化；不是重画一条简化方框链。
- `insight-mechanism`：前后对照或分片/时间/设备泳道，辅以必要公式。
- `insight-evidence`：主图/表与少量结论并列，表中给测试条件或理论条件。

按问题组合，页数服从信息，不插入无必要的封面、目录和结束页。

## 绘图完整性

整体模型保留输入、主干重复层、分支、缓存、输出及关键跳连。版本对比基于已知基线标明实际增量；继承部分不任意改画。输入输出和 shape 用普通文字，Cache 用矩形；只有解释实际分片/布局时才画有意义的张量网格。计算域用虚线围栏，归约用汇聚/运算符，通信路径直接标注 collective 与参与域。填充色可区分结构，图中文字统一黑灰，关键变化用红色；颜色必须配标签，不能仅靠颜色识别。

有用户参考图时，读取 [reference-diagram-fidelity.md](reference-diagram-fidelity.md)。先对照主干、分支、回路与缓存，再画图；不得只学配色和矩形样式。

模型结构图优先走读 vLLM-Ascend 的模型入口、backend 与算子路径，继承部分查匹配版本的 vLLM，同时用模型 config 交叉核对层型与维度。没有对应 Ascend 实现时，再用 HF 源码或用户提供的结构/实现材料建立拓扑。先核对 Ascend patch/覆盖再判断是否继承上游，方法见 [runtime-static-analysis.md](runtime-static-analysis.md)。论文示意、模型实现和硬件部署视图可以分层画，不把三者混成一张不一致的图。

昇腾运行图优先使用已核对的 Ascend 执行路径，保留关键融合算子及 shape 变化。找不到运行实现时按已知小算子/模型语义表达，并说明未核实的部分，不能用 HF 小算子链代替已存在的 Ascend 融合实现。

## 昇腾亲和性

围绕算子/精度/布局、权重和混合 Cache、通信、Prefill/Decode、TP/EP/PP/PCP/DCP、P/D 同机或分离展开。A3 与 A5 分开建场景，不从卡数直接推导可见 rank。

硬件映射和容量按本次提供的清单确认，不将先前案例的卡/die/rank比例或显存容量当成通用规格。TP/PP/PCP组合需满足实际设备数，DCP不额外增加worker数；模型/后端支持单独核实。

来源与推导留在备注；理论示意、实测条件、容量假设等影响判断的内容在图表中清楚说明。

版面尽量减少大块无意义留白；图表占比、栏宽、行高和页数按内容调整，具体执行 [style-guide.md](style-guide.md) 的“尽量减少留白”规则。
