# 特性汇报首页：模型主干与新增步骤

涉及模型的特性汇报，首个内容页用“模型主干＋特性新增步骤”讲清作用位置，再用后页展开实现和进展。保留本分支的挑战＋目标或目标＋进展以及具体结论；封面不算这个内容页。洞察分析中的特性专题也可复用这一表达。非模型项目不强套模型骨架。

## 内容与图形

- 主干保留实际 Attention、FFN、状态和必要的例外层。从特性真正影响的模块引出关联线，旁侧展示启用后的关键步骤。关联线用虚线，与计算/数据流的实线分开；不是额外的数据通信，也不表示两条路径同时执行。
- 显式区分已有计算、新增计算、新增通信/合并以及替换步骤。浅蓝承载已有计算，已有状态用浅灰，浅红强调新增或替换；需要区分新增与替换时用短标签或图外说明，不能只靠同一种颜色。图内文字继续用英文与黑灰红。
- Prefill/Decode、量化配方或不同并行拓扑的路径不同就分开，只画当前条件下实际发生的步骤。通信标 collective、进程组及交换对象，在关键位置标逻辑或每 rank shape。条件触发与后备路径写清，不能为了突出新增而把已有 FIA、投影或通用 chunk merge 也标成新增。
- 混合模型要明确特性适用于哪些层或模块。不能由一个 Attention backend 的实现推出其他 Attention、递归状态或 MoE 也走相同的通信链；未确认的状态交接和整网支持正常标为待验证。
- 首页保留足够计算上下文来解释新增步骤，但不挤入全部细节。页结论回答“在哪里增加了什么工作、换来了什么、主要代价或验证点是什么”；不要只复述特性名。按图形密度选择通栏或图配短表，原图与表格可等比缩小，文字仍要能正常阅读。

技术依据仍按 [特性源码分析](runtime-static-analysis.md#特性图)；[原图优先](technical-project-style.md#原图优先)、中文正文和华为配色规则不变。有匹配原图时本地复用，可用独立主干与关联标注补充作用位置；仅在原图缺少本次模型/新增步骤或与实现不符时按需补绘，并在备注记录原因。不能为了套本布局重画正确原图。

## 可复用局部组件

`scripts/feature_overlay.cjs` 的 `addFeatureLane(scene, spec)` 向现有二维 `Scene` 添加一段特性路径，返回具名节点。它不生成整页PPT，不提供模型数值、算子或默认通信序列。一个阶段/条件调用一次，阶段数量和位置由内容决定。

| 输入 | 含义 |
|---|---|
| `id, title, x, y, w, h` | 组件标识、英文标题和画布位置 |
| `anchor` | 已存在的受影响模型模块节点，不能使用无关占位节点 |
| `anchorPort?, scopeVia?` | 关联线端口和绝对坐标拐点；关联线不参与计算路径验收 |
| `nodes[]` | `id,label,x,y,w,h,change,kind`；坐标相对组件，节点从标题下方 `y>=50` 开始 |
| `change` | `existing / added / replaced`，只表示相对本次基线的变化 |
| `kind` | `compute / communication / merge / state`，与变化类别独立 |
| `source_refs` | 新增/替换节点的底稿证据引用；组件只保存引用，不证明源码正确 |
| `collective, group, tensor` | 通信节点必填；在英文 label 中写清，与本次代码一致 |
| `sub?, condition?` | shape 注释与可见启用条件；适当增加节点高度，避免三行内容挤在一行空间 |
| `edges[]` | 显式局部节点 `source/target`、端口、相对 `via` 与 `role`；缓存读写和分支也由调用者给出 |
| `paths[]` | 必须连通的局部节点路径，不能只声明节点存在 |

同场景继续用 `model_architecture.cjs` 的 `svg/drawio` 导出；Scene、参数和 `feature_overlays` 记录保存在本地任务目录。`auditFeatureOverlays` 检查关联到主干、节点变化分类/通信对象、条件与必经路径，检查通过仍需核对源码并实际查看图像。现有 `Scene.audit` 不包含这些特性专用检查，应同时使用。

## 验收

1. 不读后页，也能从主干找到特性的作用模块，分辨原有与新增步骤，以及 Prefill/Decode 等适用条件。
2. 与后页、底稿的算子顺序、通信组、shape 和融合边界一致；不能把“pack＋collective＋merge”封装说成整个过程单内核融合。
3. 聚合重复层时不把互斥的层类型画成同层并发；统计口径与例外层完整。虚线不混入数据流，未确认的模块不借用其他路径。
4. 实际显示比例下检查标签、边界、箭头与关联线，不压字、不穿框，不靠放大弹窗代替正常阅读。记录 Agent 实际审阅；用户确认与本次组件检查分别保存。

通用规则和局部组件可以发布；用户报告、原图、样例、模型配置、证据底稿和反馈记录留在本地。
