# 技术项目布局参考

本文件保存通用组织原则。完整参考报告、私有文件名、页码和实际项目数据留在用户项目目录，不随技能发布。

## 主体组织

| 汇报问题 | 内容组织 | 可复用单元 |
|---|---|---|
| 项目要解决什么 | 项目定位、核心挑战、对应专题 | challenge-action-column |
| 本阶段做到哪里 | 专题目标、项目节点、技术布局与总进展 | milestone-band、topic-progress-row |
| 单项方案如何支撑目标 | 挑战与目标、机制图、结果 | paired-summary、titled-corner-frame |
| 方案效果如何 | 同口径结果、必要条件和当前缺口 | comparison-table |
| 技术如何进入版本 | 技术线、版本线、交接条件与责任 | project-coordination 布局 |

## 排版原则

项目名称可直接作为标题。目标与总进展表达判断，不强迫标题写成长句口号。项目组合页可参考左侧约42%技术布局、右侧约56%进展，专题顺序和行高对应；比例随内容调整。

每个专题先写一句总进展，说明结果与缺口，再用少量短段落展开。目标、计划、实际完成与测试条件明确区分。附录可用“技术点 / 做什么 / 解决什么问题”表解释细节。

使用细灰线、短红角线、骑线标题、灰表头和选择性红字。正文紧凑但保持可读性，减少无意义留白，绘图仍遵守结构保真和黑灰红文字规范。
